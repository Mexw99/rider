หน้า 2: วิธีคิดและสูตร

ระบบคำนวณเส้นทางคิดอย่างไร

หัวใจไม่ใช่แค่ลากเส้นบนแผนที่ แต่ต้องเลือกกลุ่มงานที่มีระยะทางและเวลาเหมาะสม ภายใต้ข้อจำกัดจำนวนออเดอร์และเวลาส่ง

1. ข้อมูลนำเข้า

Inputมาจากผลต่อการคำนวณ
พิกัดร้านstoresเป็นจุดเริ่มต้นของทุกเที่ยว

2. Haversine กับ OSRM ต่างกันอย่างไร

Haversine: วัดระยะทางบนพื้นโลกจากพิกัดสองจุด เป็นเส้นตรง เหมาะกับการตรวจรัศมีร้าน 3 กม. และการคัดกรองเร็ว

Δlat = lat2 - lat1
Δlon = lon2 - lon1
a = sin²(Δlat/2) + cos(lat1)cos(lat2)sin²(Δlon/2)
c = 2asin(√a)
distance = EarthRadius × c

OSRM Table: รับหลายพิกัดแล้วคืน Matrix ของระยะทาง/เวลาแบบถนน ใช้เปรียบเทียบว่าจากร้านไปจุดใดใกล้กว่ากันจริง

OSRM Route: คืนเส้น geometry สำหรับวาดเส้นตามถนนบน Leaflet

3. การแบ่งกลุ่มแบบเข้าใจง่าย

  1. กำหนดร้านเป็นตำแหน่งปัจจุบัน
  2. ดูออเดอร์ที่ยัง PENDING และอยู่ในพื้นที่
  3. เลือกจุดที่ใกล้ตำแหน่งปัจจุบัน โดยใช้ Road Matrix
  4. เพิ่มจุดให้ Rider คนเดิมจนถึง 3 ออเดอร์
  5. ปิดกลุ่มแล้วเริ่ม Rider คนใหม่จากร้าน
  6. ลองหลาย Seed/กลยุทธ์ แล้วเลือกผลที่ดีกว่า
  7. เรียงจุดในกลุ่มให้ระยะทางสะสมต่ำ
  8. รวมเวลาและต้นทุน แล้วแสดงให้ร้านตรวจ

แนวคิดนี้คล้าย Nearest Neighbor แต่ระบบมีการลองทางเลือกและปรับปรุงเพิ่มเติม จึงไม่ใช่แค่เรียงตาม order_id

4. ทำไมต้องลองหลายทางเลือก

กลยุทธ์แนวคิดข้อดี/ข้อควรระวัง
Nearestเลือกจุดใกล้ตำแหน่งปัจจุบันเข้าใจง่ายและเร็ว แต่อาจติดกับทางเลือกเฉพาะจุด
Sweepกวาดจุดตามทิศทางรอบร้านช่วยลดการไขว้กัน แต่อาจไม่ดีที่สุดทุกพื้นที่
Farthest seedเริ่มจากจุดไกลเพื่อดึงพื้นที่เข้ากลุ่มช่วยกระจายพื้นที่ แต่อาจเพิ่มระยะทางถ้าเลือกไม่ดี
Local improvementสลับจุด/กลุ่มแล้วเก็บผลที่ดีขึ้นคุณภาพดีขึ้นแต่ใช้เวลาคำนวณเพิ่ม

5. สูตรเวลา

เวลาเดินทาง (นาที) = ระยะทางถนน (กม.) ÷ ความเร็ว (กม./ชม.) × 60
เวลาถึงจุดที่ n = เวลาออก + เวลาเดินทางสะสมถึงจุด n
ช้า = เวลาถึงจุดสุดท้าย > 12:30 น.

หากระยะทาง 3 กม. และความเร็ว 30 กม./ชม. เวลาเดินทางเชิงทฤษฎีคือ 3 ÷ 30 × 60 = 6 นาที ยังไม่รวมเวลาจอดรถและส่งของ

6. สูตรเงิน

รายรับ = กล่องทั้งหมด × 65
ต้นทุนอาหาร = กล่องทั้งหมด × 40
ค่ารอบ = จำนวน Route Plan × 15
ค่าระยะทาง = กิโลเมตรรวม × กล่องทั้งหมด × 2
กำไรเบื้องต้น = รายรับ - ต้นทุนอาหาร - ค่ารอบ - ค่าระยะทาง

ระบบอาจแสดงค่าปรับคาดการณ์แยกต่างหาก เพื่อให้ร้านเห็นว่าการส่งช้ามีความเสี่ยงต่อกำไรอย่างไร

7. ทำไมคำนวณช้า และปรับให้เร็วอย่างไร

  1. OSRM ถูกเรียกซ้ำหลายครั้ง: ใช้ Matrix ครั้งเดียวและ Cache ตามชุดพิกัด
  2. Optimizer ลองรอบมากเกินไป: ลดจำนวนรอบ เช่น 10–20 รอบตามความเหมาะสม
  3. คำนวณ Geometry ซ้ำ: Cache เส้นถนนที่ได้แล้ว
  4. โหลด API หลายครั้ง: รวม Request หรือโหลดข้อมูลที่จำเป็นพร้อมกัน
  5. จำนวนออเดอร์มาก: ใช้การคัดกรองใกล้ร้านก่อน แล้วค่อยปรับละเอียด

8. จุดเริ่มและจุดกลับร้าน

ทุก Route Plan ควรเริ่มจากร้าน เพราะอาหารถูกเตรียมที่ร้าน การกลับร้านหลังจุดสุดท้ายใช้สำหรับคำนวณระยะทางและต้นทุนรวม แต่การแสดงบนหน้าจอ Rider อาจเน้นเส้นทางไปส่งก่อน แล้วให้ปุ่มเปิด Google Maps กลับร้านเป็นทางเลือก

9. คำตอบสำหรับอาจารย์

“ระบบใช้ Haversine สำหรับตรวจระยะใกล้และใช้ OSRM สำหรับระยะทางตามถนนจริง จากนั้นสร้างหลายทางเลือกในการแบ่งงาน โดยจำกัด Rider ไม่เกิน 3 ออเดอร์ต่อรอบ แล้วประเมินด้วยระยะทาง เวลา รายรับ ต้นทุน และกำไร ก่อนให้ร้านยืนยันแผน”
