Rider Study Guideภาพรวมอ่านโค้ดการคำนวณDatabase/UML/DFDคำถามอาจารย์
หน้า 1: อ่านโค้ด

อ่านระบบจาก Route ไปถึง Database

เวลาต้องอธิบายโค้ด อย่าเริ่มอ่านแบบสุ่ม ให้เดินตามเส้นทางของข้อมูล: URL → Component → Service → Backend Controller → SQL → Response → หน้าจอ

1. จุดเริ่มของ Frontend

ไฟล์ frontend/src/app/app.routes.ts บอกว่า URL แต่ละอันใช้หน้าใด เช่น /orders, /delivery-routes, /rider/login และ /rider/work

ผู้ใช้เปิด /delivery-routes
        ↓
app.routes.ts เลือก DeliveryRoutesComponent
        ↓
delivery-routes.ts โหลดข้อมูลผ่าน Service
        ↓
route-api.ts เรียก HTTP API

ถ้าอาจารย์ถามว่า “รู้ได้อย่างไรว่าหน้านี้ทำงานที่ไหน” ให้ตอบว่าเริ่มจาก Route แล้วตาม Component ที่ Route ลงทะเบียนไว้

2. Component Angular ทำอะไร

ส่วนใน Componentหน้าที่ตัวอย่างในโปรเจกต์
importsนำ Component, Service, Forms และ Router มาใช้หน้า Customers/Orders/Delivery Routes
stateเก็บรายการข้อมูล loading error และข้อมูลที่เลือกorders, riders, selectedPlan
ngOnInitเริ่มโหลดข้อมูลเมื่อเปิดหน้าโหลดร้าน ลูกค้า ออเดอร์ Rider
methodตอบสนองการกดปุ่มsimulate, calculate, confirm, cancel
templateแสดง state เป็น HTML@if, @for, event binding

3. หน้า Orders ทำงานอย่างไร

  1. Component เรียก API โหลดออเดอร์ของวันธุรกิจ
  2. Backend JOIN ข้อมูลลูกค้าเพื่อส่งชื่อ เบอร์ ที่อยู่ และพิกัดกลับมา
  3. หน้าเว็บแสดงจำนวนกล่องและสถานะ
  4. ถ้ากดจำลอง Backend สร้างข้อมูลตัวอย่างตามเงื่อนไขธุรกิจ
  5. การแก้/ลบต้องตรวจว่า Order ยังอยู่สถานะที่อนุญาตหรือไม่

จุดสำคัญคือออเดอร์ที่มีการจัดเส้นทางแล้วไม่ควรถูกลบแบบเงียบ ๆ เพราะอาจมี route_stops อ้างถึงอยู่

4. หน้า Delivery Routes ทำงานอย่างไร

load planning store
load today's orders
load available riders
load saved route plans
        ↓
build coordinates
        ↓
request road matrix from OSRM
        ↓
optimize assignments
        ↓
calculate cost/time/profit
        ↓
show alternatives on map
        ↓
confirm selected plan

หน้าจอเป็นเพียงผู้ช่วยตัดสินใจ การบันทึกจริงต้องเกิดใน Backend ตอน Confirm เพื่อป้องกันข้อมูลถูกแก้จากหน้าจอโดยตรง

5. Backend และการแบ่งไฟล์

ไฟล์อธิบาย
backend/server.tsสร้างและเริ่ม Express Server บน Port
backend/app.tsตั้ง Middleware, CORS และ Mount Route
backend/controller/order.tsรับ Request เกี่ยวกับ Order ตรวจสถานะและเรียก SQL
backend/controller/route-plan.tsอ่าน/สร้าง/ยืนยัน/ยกเลิกแผนเส้นทาง
backend/controller/route-stop.tsอ่านจุดส่งและอัปเดตผลการส่ง
backend/services/road-matrix.tsเรียก OSRM และเก็บ Cache ระยะทาง
backend/database/rider_project_seed_v2.sqlสร้างตาราง Constraint และข้อมูลตัวอย่าง

6. Rider Login และ Rider Work

Rider กรอก Worksheet Code
        ↓
POST /rider/auth/worksheet
        ↓
Backend ตรวจ code + วัน + สถานะใบงาน
        ↓
Frontend เก็บ code ไว้สำหรับ Request ถัดไป
        ↓
GET /rider/auth/me และ GET /rider/work
        ↓
Backend ใช้ x-worksheet-code หา rider และ route plan

เหตุผลที่ Backend ต้องเป็นผู้หา Rider คือไม่ควรเชื่อ rider_id ที่ผู้ใช้ส่งเอง เพราะผู้ใช้อาจเปลี่ยนเลขแล้วเห็นงานคนอื่นได้

7. วิธีตาม Request หนึ่งรายการ

ถ้าหน้าจอขึ้น “โหลดข้อมูลไม่ได้” ให้เปิด DevTools → Network แล้วดู Request ตามลำดับ:

  1. URL ถูก Origin หรือไม่
  2. Method ถูกหรือไม่ เช่น GET/POST/PATCH
  3. Status เป็น 200, 400, 403, 404, 500 หรือ CORS
  4. Request Header มี x-worksheet-code หรือไม่
  5. Response มี JSON message อะไร
  6. เปิด Backend terminal ดู SQL error เพิ่มเติม

8. คำตอบสั้นสำหรับอธิบายโค้ด

“Frontend รับหน้าที่แสดงผลและส่ง Request ผ่าน Service ส่วน Backend รับผิดชอบ Validation, Business Rule และ SQL เพราะต้องควบคุมความถูกต้องและความปลอดภัย การคำนวณเส้นทางแยกเป็นส่วนวางแผนเพื่อทดสอบหลายทางเลือกได้ และตอนยืนยันจึงบันทึกข้อมูลจริงเป็น Route Plan กับ Route Stop”
